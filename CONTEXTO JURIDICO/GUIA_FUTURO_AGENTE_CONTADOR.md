# GUÍA DE TRANSFERENCIA FUTURA — AGENTE CONTADOR

- **Estado:** `PROPOSED`
- **No es una especificación aprobada ni una autorización para construir el contador.**
- **Propósito:** conservar desde ahora los criterios que permitirán reutilizar aprendizajes del Despacho Jurídico cuando este proyecto haya terminado.

## 1. Principio de transferencia

El Despacho Jurídico servirá como experiencia de diseño, auditoría y operación. No se debe clonar todo el proyecto ni trasladar su conocimiento especializado al agente contador.

La futura transferencia debe separar explícitamente:

1. **ADN universal reutilizable:** identidad, runtime, razonamiento, seguridad, permisos, trazabilidad, evidencia, memoria, observabilidad, pruebas, recuperación y gobernanza, solo después de verificar cuál es la versión universal vigente.
2. **Patrones de ingeniería reutilizables:** ingestión con procedencia, validación de fuentes, control temporal, abstención, evaluación adversarial y separación entre motor y conocimiento.
3. **Conocimiento jurídico no transferible como dominio:** normas, jurisprudencia, doctrina, autoridades judiciales, procedimientos procesales y reglas jurídicas.
4. **Conocimiento contable por investigar:** normas contables y tributarias aplicables, regulación vigente, autoridades competentes, obligaciones, calendarios, retenciones, facturación, nómina, estados financieros y demás funciones que se definan en una especificación independiente.

## 2. Salvaguardas

- No declarar que el ADN de AGENTE-GENERAL está congelado o certificado sin verificar su estado actual y la evidencia de auditoría.
- No asumir que una arquitectura jurídica es suficiente para obligaciones contables o tributarias.
- No reutilizar jerarquías de fuentes jurídicas como si fueran jerarquías normativas contables.
- No usar datos reales de clientes, contribuyentes, empleados, cuentas bancarias o declaraciones tributarias en ejemplos públicos.
- No emitir cálculos o conclusiones contables/tributarias sin fuentes, periodo, jurisdicción, supuestos y evidencia.
- Separar la información del usuario, datos contables, reglas normativas, cálculos, inferencias, conclusiones y acciones.
- Toda presentación, radicación, pago, declaración o comunicación externa que implique riesgo debe tener autorización humana y controles acordes con el riesgo.
- Documentar límites profesionales, necesidad de revisión humana y criterios de abstención antes de uso productivo.

## 3. Entregables que habrá que preparar al cerrar el Despacho

1. Informe final de auditoría del Despacho, con commit y evidencias reproducibles.
2. Inventario de componentes universales frente a componentes jurídicos.
3. Matriz de capacidades: reutilizable, requiere adaptación, no transferible.
4. Registro de limitaciones y errores que conviene evitar.
5. Contratos de interfaces y seguridad que se hayan verificado.
6. Especificación de objetivos y límites del agente contador.
7. Inventario de fuentes oficiales contables y tributarias por jurisdicción.
8. Plan de pruebas y criterios de aceptación propios del dominio contable.
9. Decisión explícita de arquitectura y aprobación antes de iniciar el repositorio o la implementación del contador.

## 4. Criterio para cambiar el estado

Este documento seguirá como `PROPOSED` hasta que termine la auditoría del Despacho, se determine qué base universal está realmente verificada y el propietario apruebe la especificación de transferencia. La existencia de esta guía no significa que el agente contador esté diseñado, implementado ni autorizado para operar.
